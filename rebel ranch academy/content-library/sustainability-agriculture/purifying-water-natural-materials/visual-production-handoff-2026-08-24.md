## Mandatory learner-experience requirements

### Multi-use / multi-branch

The learner may select multiple intended uses when they coexist, including supported combinations of:

- drinking/cooking;
- animals;
- irrigation/garden;
- emergency backup;
- other supported uses.

The finished experience must show shared infrastructure, branch points, why branches differ, what functions/components can be shared, what differs by branch, and a readable Whole System view.

Do not collapse this to single-select merely because it is easier to implement.

### Tangible system teaching

Visual Production must create explanatory visuals/build concepts, not primarily words in cards. At minimum, implement the approved brief's required system set, including:

- source + multi-use branch map;
- 55-gallon layered filtration cutaway/build concept;
- 5-gallon gravity system cutaway;
- settling / prefiltration / storage system;
- treatment-job map;
- historical / regional / modern comparison;
- Use What You Have matrix;
- testing decision visual;
- living My Water Plan branch diagram;
- Responsible Rebellion experiment visual;
- scale translation from countertop to larger/farm-scale systems;
- animal / irrigation distribution branches;
- approved UV function diagram;
- clear water ≠ safe water visual;
- evidence/claim ladder.

Each important visual must explain what the learner is looking at, what each part does, alternatives/substitutions where approved, strengths/limits, intended purpose, what it does not accomplish, and the learner's next action.

### Testing

Testing verifies and refines decisions; it is not permission to educate.

The product must explain what each test changes, home versus lab limits, verified affordable/free/local testing routes where the approved evidence supports them, what can be learned or built before results are known, and what specifically should wait for results.

### Living My Water Plan

The paid product must produce a substantive personalized output that materially reflects learner input. It must carry forward:

- source;
- all selected uses;
- whole-system branch diagram;
- shared infrastructure;
- branch-specific jobs;
- known facts and meaningful unknowns;
- testing status and what each test changes;
- selected system/build options;
- component/layer functions;
- substitutions and use-what-you-have options;
- justified buy points;
- verification;
- maintenance/retesting;
- failure/backup logic;
- next three actions;
- Responsible Rebellion comparison results where used.

A generalized paragraph, static template, or output that ignores meaningful learner inputs does not satisfy the approved design.

### Navigation / state

The finished experience must preserve:

- learner answers across normal navigation;
- all selected uses across the journey;
- Whole System view availability;
- optional-depth controls that return to the learner's exact previous place;
- no 404s or dead/placeholder routes;
- dependent outputs updating when earlier answers change where practical;
- My Water Plan access without re-entering answers.

Broken navigation or lost state is a Final Product QA failure.

### Learner language / visual hierarchy

Use the simplest accurate language first. Technical and evidence depth remain optional learner-chosen layers.

Prefer human task/result labels such as:

- Tell Us About Your Water;
- My Water Test Results;
- My Water Treatment Plan;
- What Happens If This Stops Working?;
- My Water Plan.

The learner should see the system before being asked to study the technical system.

`UNDERSTAND → BUILD / IMPLEMENT → OBSERVE → TEST → COMPARE → IMPROVE → DECIDE → TRANSFER THE PRINCIPLE`

### UV boundaries

UV is a microbiological-disinfection / microorganism-inactivation function, not general purification.

Preserve:

- testing/diagnosis where it changes the system decision;
- pretreatment/turbidity/clarity requirements where relevant;
- NSF/ANSI 55 Class A versus Class B;
- exact model/configuration/certified-flow limits;
- POU versus POE logic;
- non-removal of sediment, chemicals, dissolved metals and salts;
- downstream recontamination/no-residual-disinfectant issue;
- power, fouling, light-output, alarm and model-specific maintenance failure modes;
- potable-water boundary: validated/certified safety-critical UV reactor appropriate to the identified job is `WORTH BUYING / DO NOT IMPROVISE`.

Do not imply UV, boiling, chemical disinfection, solar disinfection or ordinary filtration automatically resolves unknown chemical/toxin contamination.
