# DEFERRED PROGRAMS — ORGANIZATION REQUIRED BEFORE NEW WORK

**Applies to these currently deferred program areas:**

- Roots, Boots & Animal Poops
- Back 2 the Basics — How to Survive
- Rebel Ranch Rescue

These programs do not currently have clean, dedicated program-documentation folders on `main`. Do **not** create new folder structures merely to make the repository look organized. This handoff is the controlling temporary guard until each program becomes an active priority and receives a verified organization pass.

## Purpose of This Handoff

These program areas are intentionally being left in their current state while Rebel Ranch Ministries prioritizes active, income-generating projects.

The repository has been undergoing a broader organization effort to make each program, project, system, and operating area understandable and safe for both human users and AI agents.

That organization effort is **not complete for these program areas**.

This document exists to prevent future agents from finding related files or material and beginning development, cleanup, restructuring, automation, documentation changes, or other work without first understanding and organizing what is already present.

---

## Current Status

**STATUS: DEFERRED — DO NOT MODIFY WITHOUT OWNER DIRECTION**

Material associated with these programs may include:

- Current material
- Work in progress
- Older or historical material
- Duplicate or superseded files
- Files whose purpose has not yet been verified
- Documentation that may need consolidation
- Assets or code that may still be referenced elsewhere

The presence of a file in the repository does **not** automatically mean that it is current, approved, obsolete, safe to move, or safe to delete.

No assumption should be made without verification.

## What Has Already Been Done

A repository-wide organization effort has begun.

Work completed elsewhere has established the following operating direction:

- Separate active/current instructions from historical records.
- Give programs and systems clear documentation homes.
- Reduce conflicting or duplicate agent instructions.
- Separate live/public website files from working/project material where practical.
- Preserve program boundaries.
- Avoid moving or deleting files merely to make the repository look cleaner.
- Treat files referenced by the website, workflows, integrations, Supabase, Cloudflare, GitHub Actions, or other systems as potentially runtime-sensitive until proven otherwise.
- Require verification before declaring any organizational change complete.
- Avoid allowing AI agents to expand the scope of an organization task into repair, redesign, automation development, or unrelated system work.

Several higher-priority areas have already received organization work.

These program areas have **not yet received that full review**.

## Goal When One of These Programs Becomes Active Again

Before significant new work resumes, the goal is to make that program area:

- Easy to understand
- Easy for a new AI agent to navigate
- Clear about what is current versus historical
- Clear about which files have authority
- Free of unnecessary duplication
- Properly separated from unrelated programs or systems
- Safe to maintain without breaking live functionality
- Documented well enough that future work does not depend on prior chat history

The objective is **organization and clarity first**, not rebuilding the program.

---

## REQUIRED BEFORE RELATED MATERIAL IS TOUCHED

Unless the owner specifically overrides this restriction, **organization must occur before new project work begins in one of these deferred program areas**.

Before creating, changing, moving, renaming, deleting, consolidating, repairing, or expanding related material:

1. Review all existing files, folders, documentation, branches, and references associated with the program.

2. Determine what each significant file or group of files is for.

3. Classify material as appropriate, including:
   - Current / authoritative
   - Active work in progress
   - Supporting/reference material
   - Historical/archive
   - Duplicate/superseded
   - Runtime-sensitive
   - Unknown / requires owner review

4. Identify dependencies before moving anything. This includes checking for references from:
   - HTML
   - CSS
   - JavaScript
   - imports
   - links
   - images/assets
   - GitHub Actions
   - scripts
   - sitemap or robots files
   - Cloudflare configuration
   - Supabase
   - external integrations
   - other repository documentation

5. Establish a clear program folder structure and authority document before adding significant new work.

6. Preserve anything whose status cannot be confidently determined.

7. Perform end-to-end verification for every organizational change.

## NON-NEGOTIABLE VERIFICATION RULE

Rebel Ranch Ministries requires:

**FULL VERIFICATION FOR EVERY INITIATION, CREATION, CHANGE, FIX, REMEDY, RESOLUTION, MOVE, OR DELETION.**

Do not report something as:

- fixed
- cleaned up
- organized
- complete
- migrated
- removed
- live
- safe
- resolved

unless the exact result has been verified.

A successful file edit or Git commit alone is not proof that the intended result works correctly.

## SCOPE CONTROL

This is especially important for AI agents.

If the assigned task is **organize this program area**, then organize the program area.

Do not automatically begin:

- rebuilding systems
- fixing applications
- redesigning pages
- modifying automation
- changing database architecture
- changing workflows
- expanding features
- publishing unreleased work
- merging unrelated branches
- changing live website behavior

Those are separate assignments and require separate owner direction.

If organization reveals another problem, document the problem rather than silently expanding the scope.

## OWNER OVERRIDE

The owner may override any restriction in this document.

A direct owner instruction takes precedence over this deferred status.

If the owner specifically instructs an agent to perform an urgent or income-generating task associated with one of these programs before organization is complete, that authorized task may proceed.

The agent should:

- perform only the authorized work,
- avoid unnecessary adjacent changes,
- preserve this deferred-organization status unless instructed otherwise,
- and fully verify the authorized change.
