# RRA Verification & Brand Control — NON-NEGOTIABLE

**Status:** Binding owner directive  
**Effective:** 2026-09-06  
**Applies to:** Every AI agent, developer, designer, researcher, writer, instructor, collaborator, automation, and tool working on Rebel Ranch Academy (RRA), Rebel Ranch Ministries (RRM), or related branded material.

## Controlling rule

**NOTHING HAPPENS UNLESS IT IS VERIFIED FIRST.**

Verification is a prerequisite to action, not a final cleanup step.

No initiation, creation, generation, edit, change, fix, remedy, resolution, publication, repository write, design, marketing asset, course asset, brand asset, or other implementation may proceed from an assumption when the relevant fact, instruction, source, asset, wording, state, or requirement can be verified.

If verification cannot be completed, STOP. Mark the item **NOT VERIFIED** and do not substitute, invent, approximate, recreate, infer, or proceed around the missing verification.

## Owner instructions override defaults

Explicit owner instructions are binding. An AI agent's preferred workflow, default pattern, design habit, attempt to be helpful, or desire to keep producing work may never override or bypass an explicit instruction.

If the owner says to use **our logo**, the exact approved logo must be located and verified before creation. A generated approximation, recreated mark, logo inferred from a description, similarly styled mark, or placeholder presented as the brand is prohibited.

If the owner says to use existing taglines/catchphrases, those phrases must be located in an approved source and verified before use.

## Brand verification gate

Before generating or publishing ANY RRA/RRM branded visual, page, document, course graphic, social asset, infographic, flyer, video frame, merchandise design, or similar material:

1. Identify which organization/program the asset represents.
2. Locate the canonical approved logo asset in the repository or other owner-approved source.
3. Verify the exact file/path and that the asset is appropriate for the intended background/use.
4. Make the actual verified logo available to the production/generation tool when the tool requires a source image. A text description of the logo is NOT verification and is NOT a substitute for the asset.
5. Locate and verify approved taglines, catchphrases, program names, and required brand wording.
6. Use only verified/approved existing wording.
7. Any new tagline, slogan, catchphrase, headline intended to function as recurring brand language, or other proposed brand phrase must be shown to the owner and receive explicit approval BEFORE it appears in a generated or published asset.
8. Verify the completed output itself. Confirm the correct logo is actually present, wording is correct, brand rules were followed, and no invented marks or unapproved phrases were introduced.
9. Only after end-to-end verification may the asset be described as complete/approved/ready.

## No invented branding

PROHIBITED unless explicitly requested and approved:

- invented logos;
- recreated approximations of existing logos;
- AI-generated substitutes for official marks;
- made-up seals, badges, emblems, or sub-brand marks presented as official;
- unapproved slogans or catchphrases;
- unapproved changes to existing slogans;
- unapproved program names;
- invented brand colors or visual systems when approved rules/assets exist.

New creative ideas may be proposed separately for owner review. **Proposal is not approval.** They must not be inserted into production material before approval.

## Image-generation rule

Image generation is not exempt from verification.

Before an image-generation request involving RRA/RRM branding is sent to an image generator:

- the correct logo/source asset must already be verified;
- the approved wording must already be verified;
- any new proposed brand phrase must already have owner approval;
- the generation instructions must explicitly preserve the verified brand assets rather than ask the generator to invent them.

After generation, the image must be inspected against the verified source. If the image generator alters, replaces, misspells, approximates, or invents the logo/branding, the result FAILS verification and must not be presented as a valid branded asset.

## Plain-language rule

RRA educational material must be understandable to ordinary people, including children and adults without specialized technical knowledge. Prefer plain words and direct explanations. Technical terms may be taught, but they must be explained in ordinary language.

Realistic imagery should be used where it materially helps a learner see or understand a real object, process, system, comparison, or result. Imagery exists to improve understanding, not merely decorate a page.

## Fixed-scope / finish rule

Verification does not authorize uncontrolled expansion. Follow `RRA-PROJECT-SCOPE-AND-FINISH-RULES.md` and `RRA-EDUCATIONAL-METHOD.md`.

Complete the defined version. Put nonessential discoveries into Future Expansion. Do not continually create additional material while leaving the defined deliverable unfinished.

## End-to-end verification requirement

No work may be called **fixed**, **complete**, **implemented**, **live**, **ready**, **resolved**, or equivalent without end-to-end proof of the exact requested outcome.

Examples:

- A GitHub commit proves a repository write occurred. It does NOT by itself prove a deployed website changed.
- A generated image proves an image was generated. It does NOT prove the correct logo or approved branding was used.
- Code that appears correct does not prove the user-facing workflow works.
- A document created locally does not prove it was added to the repository.

State exactly what was verified and what remains unverified.

## Incident that caused this rule to be strengthened — 2026-09-06

The owner explicitly instructed the AI to use the existing Rebel Ranch logo and existing approved taglines/catchphrases, with any newly created phrases requiring owner approval first. The AI verbally agreed, located repository evidence describing official logo assets, but then sent an image-generation request asking the generator for an “official logo” without supplying the verified actual logo asset. The generator invented a substitute logo. The generation request also included new/unapproved slogan language.

### Root cause

The failure was not lack of owner instruction. The instruction was explicit.

The failure was a process violation: the AI treated repository knowledge that an asset existed as though that were equivalent to making the verified asset available to the production tool, and it moved from verification/research into creation before completing the brand verification gate. It also treated creative copy generation as permissible despite the owner's explicit approval requirement.

### Prevention

This document converts the owner's instruction into a mandatory pre-action gate:

**VERIFY SOURCE → VERIFY ASSET → VERIFY WORDING → OBTAIN APPROVAL FOR NEW BRAND LANGUAGE → CREATE → VERIFY OUTPUT END TO END.**

If any gate is incomplete, production stops.
