# Build Your Water System — Scenario Implementation Sheets

These are system-planning examples, not universal plumbing prescriptions. The learner must use current test/source information and the approved evidence boundaries before choosing treatment.

# Scenario 1 — Private well + household drinking + no current test

## Situation
Private well, clear-looking water, household drinking/cooking, treatment need unknown.

## What we know
- source is a private well;
- intended use is potable household water;
- appearance alone does not establish safety.

## What we still need to know
Current water-quality information sufficient for the treatment decision.

## Required first function
**TEST / CHARACTERIZE.**

## Responsible path
`WELL → TEST → INTERPRET → IDENTIFY TREATMENT JOB(S) → CHOOSE POU/POE ARCHITECTURE → VERIFY → MAINTAIN/RETEST`

## UV branch
Do not jump directly to UV because the source is a well. If testing identifies a microbial-disinfection job, evaluate required pretreatment/clarity, Class A/Class B, POU/POE, certified flow, power, maintenance, and downstream recontamination protection.

## Do not assume
- clear = safe;
- one filter removes all hazards;
- UV removes chemicals/metals/salts/sediment;
- a home strip is equivalent to every laboratory test.

# Scenario 2 — Private well + confirmed microbial concern

## Situation
Testing identifies a microbiological issue requiring a disinfection function. Other water characteristics must still be considered.

## Required functions
- source protection / contamination investigation where appropriate;
- pretreatment/clarification if incoming-water conditions require it;
- validated microbial disinfection;
- suitable storage/distribution;
- verification;
- maintenance/retesting.

## UV path
`SOURCE → TEST/DIAGNOSE → PRETREAT AS REQUIRED → VALIDATED UV REACTOR → SAFE DISTRIBUTION → VERIFY / MAINTAIN`

## Buying boundary
For potable microbial disinfection, the safety-critical UV reactor is **WORTH BUYING / DO NOT IMPROVISE**. Match the exact certified class, model/configuration, flow, and operating conditions to the identified use.

## Alternative-function comparison
Depending on the situation, compare UV with boiling, chlorine-based disinfection, or solar disinfection by resources, scale, time, residual protection, consumables, operating conditions, and verification. Do not treat them as universal equivalents.

# Scenario 3 — Municipal water + renter + no plumbing modification

## Situation
Municipal source, renter cannot modify plumbing, learner has a specific taste/odor or contaminant concern.

## First questions
- What does current utility/source information show?
- Is the concern aesthetic, plumbing-related, or a tested contaminant?
- What treatment job is actually required?

## Functional path
`PUBLIC/SOURCE DATA + HOUSEHOLD CONCERN → TARGETED INFORMATION/TESTING IF NEEDED → TREATMENT JOB → NO-INSTALL POU FORMS → CERTIFIED PERFORMANCE MATCH → MAINTAIN`

## Resource rule
Do not rank pitchers, countertop RO, carbon, UV, or other devices generically. Compare only forms that perform the identified job within their supported claims.

# Scenario 4 — Rainwater + chickens + reduce daily labor

## Situation
Rainwater available; poultry watering; owner wants larger storage and automatic delivery.

## Core functions
`CATCH → EXCLUDE/REDUCE DEBRIS AS APPROPRIATE → STORE → CREATE FLOW → MOVE → CONTROL → INSPECT → CLEAN/MAINTAIN`

## Resource inventory examples
- existing roof/catchment;
- food-safe or otherwise appropriate animal-water storage;
- 5-gallon bucket / 55-gallon drum / tank;
- elevated stand;
- tubing/pipe;
- pump if gravity is insufficient;
- float valve / nipple / cup controls.

## Automation questions
- What happens if storage empties?
- What happens if a float sticks or line clogs?
- Is there a backup source?
- Can the system be drained/cleaned?
- How will water availability be checked daily without recreating the same labor burden?

## Boundary
This scenario is animal-water storage/distribution. It does not establish potable-human-water treatment.

# Scenario 5 — Pond / surface water + emergency human-use backup

## Situation
Primary source fails; pond is physically available; human drinking/cooking may be needed.

## High-caution rule
A pond is not simply “well water with more dirt.” Surface-water risk can include microorganisms plus possible chemical/toxin concerns.

## Decision path
`SOURCE RISK → INTENDED USE → WHAT IS KNOWN/UNKNOWN → PRETREATMENT AS APPROPRIATE → MATCHED TREATMENT/DISINFECTION → SAFE STORAGE → VERIFY`

## Stop condition
If harmful chemical/toxin contamination is possible or unknown, do not imply that ordinary filtration, boiling, chlorine, solar disinfection, or UV automatically makes the water safe. The unresolved chemical/toxin question must be handled separately.

## Think Like a Rebel lesson
The existence of a resource does not prove its suitability for every use. Inventory the resource, then test it against the required performance and safety boundary.

# Scenario 6 — Scale translation: 5 gallons to 55 gallons

## Goal
Move from a small portable storage concept to larger farm/homestead storage.

## Function that stays the same
**STORE.**

## Constraints that change
- weight and structural support;
- portability;
- outlet height;
- gravity/head pressure;
- fittings and flow;
- overflow;
- cleaning access;
- material suitability;
- stagnation/rotation;
- protection from contamination;
- maintenance burden.

## Design lesson
Scaling is not “use a bigger bucket.” The function can stay the same while the engineering conditions change.

# Scenario 7 — Demonstration filter for family learning

## Goal
See settling, straining, particle filtration, flow, and media behavior.

## Safe use
Use simulated dirty water and the approved `Dirty Is Visible. Danger Isn't.` activity.

## What the activity can show
- visible-particle reduction;
- clarity changes;
- flow differences;
- layer loading/clogging;
- effect of changing one variable.

## What it cannot prove without appropriate testing
Potable-water safety or removal of hazards that were not measured.

## Transfer
Observation is evidence of what was observed—not automatic evidence for every larger claim.
