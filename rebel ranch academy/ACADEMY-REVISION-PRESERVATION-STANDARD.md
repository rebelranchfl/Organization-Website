# Rebel Ranch Academy — Revision Preservation Standard

**Status:** Owner-approved non-negotiable working standard  
**Approved:** 2026-08-21  
**Applies to:** Every RRA content project, owner review, revision, agent, dashboard workflow, and automation

## Core rule

**`NEEDS MORE WORK` is additive by default.**

When the owner asks for more work, the agent must preserve all useful, accurate, owner-approved, or still-valid existing material and add, strengthen, clarify, reorganize locally, or correct only what the owner's comments require.

A revision request does **not** authorize the agent to replace the project's original concept, research foundation, teaching structure, activities, source set, pricing logic, or master content simply because the new feedback suggests an interesting broader direction.

## Replacement requires explicit owner direction

An agent may substantially replace, remove, or rebuild existing material only when the owner explicitly directs language or intent such as:

- replace this;
- remove this;
- delete this section;
- restructure the entire project;
- change the direction;
- start over;
- abandon the original concept;
- use the new concept instead of the old one.

If owner comments do not explicitly authorize replacement, **preservation is the default**.

## Mandatory revision impact check

Before changing an existing project after `NEEDS MORE WORK`, the agent must identify:

1. **KEEP** — existing material that remains useful, accurate, aligned, and should survive unchanged or nearly unchanged;
2. **ADD** — new material specifically requested by the owner;
3. **STRENGTHEN** — existing material that needs deeper research, more examples, better sourcing, clearer teaching, or better application;
4. **CORRECT** — material shown to be inaccurate, unsafe, unsupported, outdated, duplicated, or inconsistent with owner direction;
5. **REMOVE/REPLACE** — allowed only when explicitly authorized by the owner or when evidence/safety makes continued use indefensible, in which case the reason must be documented.

The revision record must show this impact check before polished rewriting begins.

## Baseline preservation

Before a substantial revision, preserve the pre-revision baseline in Git history and, for major owner-review revisions, in a clearly identifiable project backup or revision-baseline file.

The final project should be traceable so a future agent can answer:

- What existed before the revision?
- What did the owner ask to add/change?
- What was retained?
- What was added?
- What was corrected or removed, and why?
- Did the revision expand the project or unintentionally replace it?

## Additive integration rule

When owner feedback expands scope, the new structure should normally be:

**existing foundation + requested expansion = richer project**

not:

**requested expansion = replacement project**

Agents should integrate new material where it teaches best while retaining the earlier project's valuable depth. Condensing repeated language is allowed; deleting a distinct concept, example, experiment, evidence path, or teaching principle merely to make room for new material is not.

## Owner review rule

A later owner approval does not retroactively authorize accidental removal of earlier material the owner expected to remain. If the owner discovers that a revision replaced rather than expanded prior work, that discovery reopens the project for corrective integration even if the latest revision had been approved.

## QA requirement

Before returning a revised project to `READY FOR REVIEW`, QA must compare the revision against its baseline and confirm:

- owner-requested additions are present;
- useful prior material is still present;
- no distinct prior teaching value disappeared without a documented reason;
- any removed/replaced material has explicit owner authorization or documented evidence/safety justification;
- the result is an integrated project rather than a silent direction change.

## RRA-2026-0001 precedent

The first Water Through the Layers test project exposed this missing safeguard. Revision 2 broadened the project into global water practices, copper, frequency/energy, and lunar-human evidence, but it also replaced substantial Revision 1 filtration/natural-material research and teaching structure rather than adding to it.

The corrective standard for that project is:

**Revision 1 filtration/natural-material foundation + Revision 2 global/copper/frequency/lunar expansion = one comprehensive Water Through the Layers project.**

This precedent is now the permanent revision rule for RRA.
